# Changelog

All notable user-facing changes to CHMReaderLight are documented here.

## Unreleased

- Fixed the GitHub social preview title and supporting copy being obscured by the product window, added a reproducible 1280 x 640 PNG generation command, and made asset checks reject stale SVG/PNG pairs.
- Star calls to action now open the repository page where GitHub exposes the Star control instead of the read-only stargazer list.
- Security: replaced Homebrew CHMLib release vendoring with a pinned, SHA-256-verified source build carrying the CVE-2025-48172 bounds-check backport, bundled corresponding source, and final-binary provenance verification.
- Security: macOS packaging now applies production Electron fuses before the final signature, disabling unused Node and debugging entry points, requiring the app entry point to load from ASAR, and enabling embedded ASAR integrity validation; final bundle verification reads every expected fuse state back and matches the signed plist metadata to the packaged ASAR header.
- Fixed ad-hoc macOS packages being signed with an unintended hardened-runtime flag that passed static signature verification but prevented Electron Framework from loading; release verification now checks every bundled Mach-O file and rejects that non-launchable signature combination.
- Fixed packaged CHMLib deployment targets so native extraction remains compatible with the documented macOS 12 minimum instead of inheriting the CI runner's host OS version.
- Fixed macOS packages embedding stale release zips, tests, sources, and other repository-only files; the runtime ASAR is now restricted to compiled assets, production dependencies, package metadata, and license notices.
- Fixed failed application-menu actions so their error reporting also remains safe after the main window closes or if Electron's error dialog itself fails.
- Fixed failed CHM opens so best-effort cache cleanup cannot replace the original extraction or validation error.
- Fixed clearing the extracted cache while reading so the app returns to the library instead of leaving the reader pointed at deleted resources.
- Release artifact verification now requires each checksum file to name its matching architecture artifact and hashes large archives incrementally.
- macOS packaging now keeps the generated bundle icon out of `app.asar`, and release verification rejects that redundant packaging asset.
- Release publishing now snapshots every asset's size and SHA-256, binds each snapshot to its matching checksum declaration, rejects files changed after verification, uploads from the verified open file rather than reopening a replaceable path, and hashes the exact streamed bytes before allowing a draft to become public.
- Confirmed manual publishing now requires the full 40-character build commit SHA so a new release tag cannot silently target unrelated default-branch source.
- GitHub Actions dependencies are pinned to immutable commit SHAs with readable version annotations.
- Malformed percent escapes in untrusted CHM topic paths no longer interrupt reader navigation synchronization.
- Live repository listing fallbacks now fail closed when GitHub HTML cannot prove required About or Discussions fields, and Homebrew cask preparation exits nonzero when release artifacts are incomplete.
- Native CHM extraction now discards verbose helper progress output while retaining bounded stderr diagnostics, so valid large archives are not rejected by an output-buffer limit.
- Library mutations now publish availability-enriched snapshots in persistence order, and macOS path comparison normalizes case and path segments before duplicate checks.
- Failed startup encoding restoration no longer deletes the user's saved encoding preference.
- macOS bundle verification now checks every Electron fuse wire in universal binaries instead of trusting only the first architecture slice.
- Release publishing now re-verifies the public tag and asset set immediately after publication and returns a changed release to draft when possible.
- Removed the Release attestation job's unnecessary `artifact-metadata: write` permission; file attestations keep only the documented contents-read, attestation-write, and OIDC permissions.

### Added

- Added target-architecture macOS packaging preflight commands that validate CHMLib binaries before expensive release builds.
- Added deterministic SVG-to-PNG app icon rasterization before building the macOS iconset.
- Added final ad-hoc signing and strict verification for packaged macOS app bundles.
- Added shared macOS release artifact commands for local and GitHub Actions zip/checksum generation.
- Added final macOS release zip inspection for an allowlisted archive root, bundle signatures, architectures, CHMLib linkage, metadata, exact branded icons, and a 20 MiB runtime ASAR budget.
- Added atomic GitHub Release publishing that waits for both macOS architectures and verifies all four downloadable files before creating a public release.
- Added opt-in manual GitHub Release publishing with strict semantic tag validation and build-only behavior by default.
- Added per-version Release workflow concurrency protection so duplicate publish requests cannot run at the same time.
- Updated release provenance generation to the unified `actions/attest@v4` action.
- Security: isolated the Release workflow's OIDC and attestation write permissions in a dedicated post-build job, keeping dependency installation and macOS packaging read-only and requiring successful attestations before publication; disabled checkout credential persistence across Release jobs, moved artifact preflight and post-publish verification into read-only jobs, and bound the three-step publisher job to an allowlisted input by its exact immutable artifact ID. GitHub Actions permissions remain job-scoped, so the documented write-token trust boundary explicitly includes only the two fixed-SHA runtime/download actions and the direct publisher invocation.

- Manual release publishing now streams large assets into a draft and exposes the Release only after every architecture and checksum upload succeeds.
- Local release packaging now refuses to overwrite an existing same-name zip or checksum before starting the build, validates temporary output before publishing final filenames, and cleans failed or interrupted partial output.
- Manual release dry runs now reject malformed tags and tags that do not match `package.json`, matching the GitHub Actions release guard.
- Automated Releases now use the draft-first streaming publisher, bind newly created tags to the exact workflow commit, and run tag-specific verification only after atomic publication.
- Confirmed release publishing now resolves existing lightweight and annotated Git tags and refuses any tag whose final commit differs from the build SHA before touching Release state.
- The post-publish remote Release gate now verifies that the Git tag still resolves to the exact build commit, closing tag-move races around publication.
- Release uploads now verify GitHub's server-reported asset name, size, and SHA-256 digest, then re-read the complete draft to reject concurrent publication or missing, duplicate, extra, incomplete, or replaced assets before exposing it; the post-publish gate compares all four remote assets with the locally verified files.
- Exact release provenance checks now fail closed on GitHub API rate limits instead of treating asset-only HTML fallback evidence as sufficient.
- Interrupted automated Release uploads can now safely resume matching private drafts without overwriting public Releases or deleting unexpected assets.
- Reader navigation bridge messages now require the active CHM iframe as their source before opening external links or updating navigation state.
- Main-window navigation and popup requests are now denied, preventing remote pages from replacing the trusted local renderer.
- Reader frame navigation is now restricted to the local `chm://book` origin, blocking remote iframe redirects before they load.
- Browser permission checks and requests are now denied because the reader does not require web platform device permissions.
- Main-process IPC handlers now reject calls from anything other than the active app window's main frame.
- Search inputs and main-process search handling now cap normalized queries at 200 characters to avoid excessive work from accidental large pastes.
- Native CHM extraction now has a two-minute timeout and bounded process output so damaged files cannot leave the open flow waiting indefinitely.
- Native CHM extraction now rejects oversized or overpopulated archives before the packaged helper writes an entry, treats partial writes as failures, and independently rejects oversized trees, symbolic links, and special files before metadata parsing or search indexing.
- Bounded in-memory HTML and HHC transforms to 16 MiB per page and capped each search index at 128 MiB of source HTML, while preserving streaming delivery for non-HTML resources.
- Rejected incomplete markup reads even when filesystem metadata still reports the original size, preventing truncated pages from being decoded after an unexpected short read.
- Capped per-page search match counting and highlighting at 10,000 and stopped scanning after 100 matching pages to bound adversarial query work.
- Bounded HHC table-of-contents parsing at 50,000 items and 256 nesting levels to prevent compact markup from creating unbounded navigation trees.
- Reused bounded asynchronous extracted-tree scans for metadata discovery and revalidated the tree in the search worker, removing an unbounded synchronous main-process traversal.
- Empty or incomplete extracted caches are now rejected so the next open rebuilds them instead of reusing a permanently blank result.
- Extracted-cache identity now includes device, inode, size, and nanosecond modification and change times, is checked before publishing a new extraction, and is checked again after cached reads or publication before activating the opened-book state. New staging directories share the final cache filesystem for atomic rename, and failed final checks remove a just-published cache, preventing stale reuse when a CHM is replaced rapidly during either path.
- Serialized overlapping CHM open, text-encoding reload, and cache-clear transactions in the main process so cache publication and active-reader state remain deterministic across UI, Finder, second-instance, and maintenance entry points.
- Text-encoding reloads now keep the previous active encoding when reparsing the open book fails.
- Background search-index worker startup failures now degrade without rejecting an otherwise successful book open or text-encoding reload.
- Last-opened metadata write failures no longer report an already opened CHM as failed.
- Library book-open request failures now leave the loading state and return to the library instead of stranding the reader on an unhandled rejected request.
- Library startup failures now show an accessible error state with details and a retry action instead of leaving a blank library and an unhandled rejected request.
- Collection create and rename failures now keep the dialog usable, announce an inline error, and restore the submit action for correction or retry.
- Library import, drag-and-drop, relink, Finder reveal, document removal, and collection deletion failures now surface actionable errors without leaking rejected event promises.
- Reader body-search and topic-navigation request failures now preserve the current reading state, report the failure, and avoid unhandled rejected promises.
- Main-process view synchronization and external-link failures now consume and report rejected IPC requests instead of leaking unhandled promises.
- Application menu actions now consume rejected promises and report failures instead of leaking unhandled rejections.
- Main-process startup, window loading, and background-worker shutdown now consume and report rejected lifecycle promises.
- Finder, command-line, and second-instance CHM open failures now show an error instead of being silently ignored.
- Body-search highlighting now preserves encoded HTML-like text instead of reinterpreting it as document markup.
- Library metadata now uses atomic file replacement and surfaces corrupt JSON instead of silently treating damaged state as an empty library.
- Bounded library metadata reads and writes at 16 MiB, rejected symbolic-link inputs, and preserved existing state when a write would exceed the limit.
- Bounded persisted library state at 10,000 books and 1,000 collections, validated persisted library fields and string lengths on both read and write, stripped transient availability fields before persistence, and capped source availability checks at 16 concurrent file probes.
- Serialized library read-modify-write operations so overlapping imports, removals, collection edits, relinks, and last-opened updates cannot silently overwrite each other.
- Finder and command-line opens now select the requested CHM when that file already exists in the library instead of opening the last library item.
- Capped library source availability checks at 16 concurrent file probes to avoid large-library I/O bursts.
