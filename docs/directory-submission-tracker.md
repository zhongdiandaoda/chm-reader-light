# Directory Submission Tracker

Use this template after CHMReaderLight is submitted to app directories, open-source macOS app lists, developer-tool indexes, or documentation-tool collections. Keep public listing follow-up in one place so descriptions, tags, screenshots, and download links stay accurate after releases.

Status values can be `Planned`, `Submitted`, `Live`, `Needs update`, `Rejected`, or `Retired`. Use the follow-up column for reviewer notes, requested edits, next check dates, or stale listing cleanup.

Use `High`, `Medium`, or `Low` priority to keep the next outreach batch focused. Use Source for the saved search, community list, or referral that produced the candidate.

Record baseline GitHub stars, release downloads, and watchers when you submit, then compare them during follow-up checks so maintainers can see which external listings are worth updating or repeating. Capture a dated evidence note for every follow-up check, including live listing status, release-feedback themes, support issues, or showcase stories that explain the metric change.

## Listing Quality Check

- The description matches the current repository About panel and package metadata.
- The tags match CHM, offline documentation, macOS, Electron, and reader search terms.
- The canonical project link points to the GitHub repository README.
- The download link points to the latest GitHub Release when the directory has a dedicated download field.
- The release version matches the artifacts users can actually download.
- The screenshots or preview images do not include private CHM content, sensitive file paths, customer names, or confidential document text.
- The listing does not claim Windows, Linux, cloud sync, broad CHM compatibility, notarization, Homebrew availability, or automatic updates before those items are shipped and documented.

## Follow-Up Cadence

Recheck live listings after each public release, after changing the repository description or social preview, and before a larger sharing push. Mark listings as `Needs update` when their copy, tags, screenshots, download URL, or trust notes no longer match the repository.

When a directory no longer accepts the project scope or points users to stale artifacts, either update the listing or mark it as `Retired` so future promotion work does not reuse it.
