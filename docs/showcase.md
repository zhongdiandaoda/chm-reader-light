# Showcase Guide

Use this guide when a user wants to share how CHMReaderLight helped their offline CHM workflow. The goal is to collect real examples that future visitors can trust without inventing testimonials or exposing private documents.

## What to Share

- The offline CHM workflow, such as managing legacy SDK manuals, vendor help files, or archived API documentation on macOS.
- Describe what changed after using CHMReaderLight, such as faster reopening, easier library search, safer local-only reading, or clearer compatibility reporting.
- Which feature helped most: library organization, searchable table of contents, body search, reading history, Finder actions, diagnostics, or release packaging.
- Safe context such as macOS version, Mac architecture, install source, CHM language, and approximate library size.

## Privacy Rules

- Do not include private document content, proprietary screenshots, sensitive file paths, customer names, internal product names, or confidential CHM text.
- Redact screenshots and copied diagnostic output before posting publicly.
- Confirm quote permission before reusing a story outside the original issue or discussion.
- Use anonymous wording when the reporter asks not to be named.

## How Maintainers Can Reuse Stories

- Link a relevant story from README when it helps first-time visitors understand a real workflow.
- Mention short, permissioned highlights in release notes when a change directly improves the reported workflow.
- Update the Share Kit with clearer audience language after repeated stories reveal the same use case.
- Keep claims specific to what the reporter described; do not generalize one story into broad compatibility promises.
