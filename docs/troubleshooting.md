# Troubleshooting

This guide covers the most common CHMReaderLight setup and document issues on macOS.

For supported CHM patterns, known limits, and issue-report details, see [Compatibility Notes](./compatibility.md).
For downloads and local data behavior, see the [README](../README.md) and [Privacy](./privacy.md).

## App Cannot Be Opened

If macOS blocks the app because it was downloaded from the internet, open **System Settings > Privacy & Security** and allow CHMReaderLight to run.

If the app was built locally, run:

```bash
npm run package:mac
```

Then open the `.app` from the generated `dist/` folder or install it with:

```bash
npm run install:mac
```

## CHM File Does Not Open

CHMReaderLight reads `.chm` files through `extract_chmLib`. Packaged builds include a pinned, CVE-patched native extractor. Local development runs still need a system CHMLib, while self-packaging builds and vendors the audited source automatically.

Check the local environment:

```bash
npm run doctor
```

If you are packaging the app yourself, run `npm run check:package:mac:arm64` to verify the required Xcode tools. The package command then builds and validates the pinned CHMLib source for Apple Silicon. Use the GitHub Actions release job when you do not have Apple Silicon hardware locally.

## Text Looks Garbled

Older CHM files often use legacy encodings. In the reader toolbar, open the text encoding menu and try:

- Simplified Chinese: `GBK` or `GB18030`
- Traditional Chinese: `BIG5`
- Japanese: `Shift-JIS` or `EUC-JP`
- Korean: `EUC-KR`

Use the default encoding again if the CHM already declares a correct charset.

## Table of Contents Is Missing

Some CHM files do not include an `.hhc` table of contents, or include one with unusual markup. The document may still open its default page even when the sidebar is empty.

When reporting this, include whether the body page loads and whether the affected CHM can be shared privately for reproduction.

## Search Shows Fewer Results Than Expected

Full-text search is built from extracted HTML pages. Large books can take a moment before the search index is ready. If the document just opened, wait for indexing to finish and try again.

Search works best with visible body text. Text generated by scripts, embedded images, or unsupported binary content may not be searchable.

If search or page rendering still looks stale after replacing a CHM file, choose **Help > Clear Extracted Cache**. This removes only cached extracted contents; your source CHM files and library entries remain in place.

## Library Entry Cannot Be Found

The library stores source file paths instead of copying CHM files. If a file was moved, renamed, or deleted outside CHMReaderLight, the saved entry can no longer be opened or revealed in Finder.

If the CHM still exists at a new location, use the relink action on the missing library card and choose the moved file. This updates the saved path while keeping the library entry, collection, added date, and reading metadata. If the source file was intentionally deleted, remove the stale entry from the library.

For deeper troubleshooting, choose **Help > Reveal App Data Folder** to inspect the saved library metadata and extracted-book cache.

## Before Opening an Issue

In the app, choose **Help > Copy Diagnostic Info** and paste the copied block into the issue. It includes the app, Electron, Node, platform, architecture, and macOS Darwin version without including document paths or CHM content.

Please include:

- macOS version and Mac architecture
- CHM language and approximate file size
- Whether the table of contents, body page, or search is affected
- The smallest reproduction steps
- Screenshots or logs with private content removed
