# CHMReaderLight 中文搜索指南

[English Search Guide](./search.md)

CHMReaderLight 把搜索分成三条路径：在书库里找书、在目录里找章节，以及在当前 CHM 的正文中找文字。

## 书库搜索

还没决定打开哪本手册时，使用书库搜索框。它会匹配每本书的书名或源文件路径，适合管理大量 SDK、API 或产品文档目录。

如果过滤后的视图没有结果，可以使用空状态中的操作清空关键词，返回当前书库分组。

## 阅读器搜索

打开 CHM 文件后，按 `Command+F` 聚焦阅读器搜索框。搜索范围菜单可以切换：

- Body：在当前 CHM 已索引页面的提取 HTML 正文文本中搜索。
- Directory：按章节标题过滤 table of contents。

当你知道函数名、错误字符串、命令或配置项时，Body 搜索更有用。已经知道大致章节或主题标题时，Directory 搜索通常更快。

选中的搜索范围会保存在本地，因此下次打开阅读器时会沿用同一个 Body 或 Directory 模式。

## 匹配项导航

正文搜索会在侧栏标记包含匹配项的章节，并高亮当前页面中的匹配文本。可以使用工具栏上的上一个/下一个匹配项按钮，在当前页面的结果之间移动。

匹配项计数器显示你在当前页面中的位置；搜索状态会显示整本书的总匹配数和命中章节数量。
为避免异常重复内容无限放大处理量，计数和高亮最多处理每页 10,000 个匹配项。

## 索引限制

全文搜索基于提取后 HTML 页面中的可见正文文本。较大的书打开后可能需要一点时间完成索引。

为保持可预测的内存使用，每个被索引的 HTML 页面上限为 16 MiB，每本书按顺序纳入索引的源页面总量上限为 128 MiB。超过单页上限的页面会被跳过；下一页会突破总预算时，索引会停止，因此特别大的书籍中，后续页面可能不会出现在正文搜索结果中。

搜索不会覆盖只存在于图片、脚本生成内容、嵌入式二进制对象或不受支持 plugin content 中的文字。

如果替换 CHM 文件后搜索结果像是旧内容，请选择 **Help > Clear Extracted Cache** 并重新打开文档。报告 CHM 专属搜索缺口时，请包含受影响的搜索关键词和 **Help > Copy Diagnostic Info** 输出。
