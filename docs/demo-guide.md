# Demo Guide

Use this guide when recording a short README video, release-note clip, or social preview walkthrough. The goal is to show the real CHMReaderLight workflow quickly, without exposing private document content. Use the [Sample CHM Guide](./sample-chm-guide.md) when choosing public or synthetic files for the recording, and pair it with the [Share Kit](./share-kit.md) before publishing release or social copy.

## 60-Second Flow

- Start in the library view with one or two safe sample CHM files already available.
- Drag one or more `.chm` files into the library window and show that the app keeps the original source file in place.
- Switch between grid and list layout, then filter the library by book name or source path.
- Open a book and filter the searchable table of contents.
- Run a body search, move between matches, and copy the current topic reference.
- Change zoom or text encoding to show reader preferences without leaving the document.
- Use **Help > Star on GitHub** at the end if the demo is meant for project sharing.

## Capture Checklist

- Use a disposable CHM file, synthetic CHM, or public manual that can be shown.
- Do not show private document content, private file paths, internal product names, or unreleased customer material.
- Keep the app window large enough to show the library sidebar, book list, table of contents, and reader toolbar clearly.
- Prefer a short, continuous recording over several disconnected clips.
- If the demo is attached to a release, mention whether the build is Apple Silicon or Intel and whether it came from GitHub Releases or a local package.
- Recheck [Privacy and Local Data](./privacy.md), [Security Model](./security-model.md), and [Compatibility Notes](./compatibility.md) before publishing a public walkthrough.
